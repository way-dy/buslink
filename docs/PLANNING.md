## 1. 시스템 정의
- **BusLink** — 동영관광 통근버스 GPS 실시간 관제 시스템. 설치형 네이티브 앱 없이 **웹앱(PWA)** 으로 제공("웹앱"이라 부르지 말고 "설치 없이 링크 하나로 시작"으로 표현).
- 단계 비전: ① 동영관광 자체 운영(300대)으로 완성·안정화 → ② `companyId` 기반 멀티테넌트 전환 → ③ 타 관광사 대상 **SaaS** 영업. 핵심 영업 메시지 "300대로 직접 쓰고 있습니다".
- 운영 전제: 기사 폰 차량 거치대 + 상시 충전 + Wake Lock. iOS Safari 백그라운드 위치 한계는 거치 환경으로 회피(불가 시 Capacitor 하이브리드 — 보류 옵션).

## 2. 사용자 역할 (계정 레벨)
| Lv | 역할 | 인증 | 핵심 사용 |
|---|---|---|---|
| 0 | 슈퍼관리자(동영관광) | 이메일+PW | SaaS 가입사·빌링·전체공지 |
| 1 | 회사관리자(관광사) | 이메일+PW | 노선/기사/차량/배차/운행일지 |
| 2 | 센터·지사관리자 | 이메일+PW | 지점 범위 관리 |
| 3 | 고객사담당자(기업 인사팀) | (추정) | 자사 노선/사원 조회·실시간 버스위치·탑승현황·공지수신 |
| 4 | 기사 | 사번+PIN(6자리) | 배차 자동표시·운행시작/종료·GPS·QR스캔·정류장체크·공지 |
| 5 | 승객(사원) | 사번+PIN | 버스 ETA·실시간 위치·QR 탑승체크인·공지 |

- 인증 확정: 기사/승객 = 사번+PIN(합성 이메일 `{사번}@buslink.com` + PIN=Firebase password, `.internal` 금지). 관리자/센터 = 이메일+긴 비밀번호. 전화번호 비수집(개인정보 리스크 회피), 휴대폰 SMS 인증은 **선택 병행**.
- 온보딩: 관리자가 사번+초기PIN 일괄등록(엑셀) → 첫 로그인 시 PIN 변경 강제 → 이후 SMS 선택 등록 가능.

## 3. 앱 분리 (URL 분리 채택)
- `admin.*` — 회사관리자 + 고객사담당(권한 구분, 동일 URL)
- `driver.*` — 기사 전용(PWA 홈화면 설치 권장)
- `bus.*`(passenger) — 승객(설치 없이 URL만)
- `super.*` — 슈퍼관리자
- 멀티테넌트 시 서브도메인 또는 경로(`/회사/admin`) 방식. 단일 URL+로그인 후 분기 방식은 비채택(느림·코드혼재).

## 4. 기능 요구사항
### 4.1 기사 앱
- 로그인(사번+PIN) → **오늘 배차 자동 표시**(기사가 선택 X, 확인만) → `[운행시작]` 1탭으로 GPS 전송 → `[운행종료]`. 배차 없음/2개/긴급변경 예외 처리(+푸시 자동반영).
- GPS: `watchPosition`, 10m 이동 미만 스로틀, `gps/{companyId}_{vehicleId}` 덮어쓰기 + `gpsHistory` 누적. `enableHighAccuracy:true`. 음영지역 = 마지막 위치 유지+"신호 없음", 재연결 자동복구, 운행중 끊김 시 관리자 알림.
- QR 탑승 스캔, 정류장별 도착 체크, 긴급공지 수신.

### 4.2 관리자 앱 (탭 구조)
- **실시간 관제**: 300대 카카오맵 지도, 차량목록(운행중/대기), 차량 클릭 → 상세(좌표·속도·정확도·노선)·panTo.
- **노선 관리**: 출근/퇴근 탭, 요일별 스케줄(시작/종료), 정류장은 노선 저장 후 2단계 설정, 탑승률 낮은 노선 색강조, 엑셀 등록/다운로드.
- **배차 관리**: 날짜별 등록/수정/삭제, 출/퇴근→노선→기사/차량 강제배차.
- **기사 관리**: 목록/등록/삭제, 접속완료/미접속·OS기종 표시, **등록 시 Auth 계정 자동생성 / 삭제 시 Auth 동시삭제(Cloud Function)**.
- **차량 관리**: 300대 등록/상태.
- **운행일지/운행기록**: GPS 궤적 지도(점), 정류장별 도착예정 vs 실제·정상출발/미정차 색상, 조출여부, 승/하차 인원(마스킹 토글).
- **탑승객 분석**: 노선별 태깅인원 vs 수기 입력, 태깅률, 탑승객 리스트.
- **예약 정보 관리**: 탑승여부·미탑승/완료·예약취소 색상 구분.
- **푸시 발송**: 기사 푸시(2단 레이아웃·전체/개별), 고객 푸시(노선별·예약자만/전체·즉시), 제목20/내용255 제한. FCM 500개 배치+간격.
- **공지사항**, **설정**(하위계정·센터 할당).

### 4.3 고객사 담당자 포털
- 자사 노선만 조회, 실시간 버스 위치, 탑승객 현황 대시보드, 공지 수신, 사원에게 링크 배포.

### 4.4 승객 앱
- 내 버스 실시간 위치 지도 + **ETA 카운트다운**, 오늘 운행정보(출발·기사연락처), QR 탑승 체크인, 공지·푸시(PWA 설치 시).

### 4.5 슈퍼관리자
- 가입사 현황(활성/만료), 매출 그래프, 회사별 사용량, 회사 계정 생성/정지/해지, 플랜/요금, 전체공지 일괄.

### 4.6 공통
- 정류장 위경도 입력 3방식: **A 지도 클릭(권장)** / B 카카오 주소·키워드 검색 / C 엑셀 일괄.
- 부정승차 방지: 블루투스(iOS 불가)·NFC·QR·예약코드 비교 → **QR/사번 방식 채택**(초기 예약코드 `DY-2847` 단체전세안은 통근형 확정으로 폐기).

## 5. 데이터 모델 (멀티테넌트 — 전 컬렉션 companyId)
```
companies/{companyId}/
  routes/{routeId}/stops/{stopId}
  drivers/{driverId}            // name, uid, vehicleId, status, OS, ...
  vehicles/{vehicleId}
  dispatches/{date}/list/{dispatchId}  // driverId, routeId, routeName, vehicleNo/Id, departTime, status
  passengers/{passengerId}
  boardings/{date}/list/{id}
  fcmTokens, notices
users/{uid}                     // role(superadmin/admin/center/driver), companyId  ← 권한 게이트
gps/{companyId}_{vehicleId}     // lat,lng,accuracy,speed,companyId,driverId,routeId,updatedAt
gpsHistory/{companyId}/{vehicleId}/{date}/points/{id}
boardingTokens, partnerCodes, fcmQueue
billing/{companyId}             // 슈퍼관리자 전용 (SaaS)
```
- 보안규칙 모델: 초기안은 커스텀 클레임(`token.role`/`token.companyId`) → **현 정본은 `users/{uid}` 문서 조회 방식**(설계 진화, 차이 인지).

## 6. 기술 스택·결정
- CRA(React) SPA + PWA, react-router 없음(경로 수동분기). Firebase: Auth / Firestore(서울 리전) / Hosting(HTTPS, SSL 자동) / Functions / FCM(VAPID). 프로젝트 `buslink-prod` 단일.
- 지도: 카카오맵 SDK `<script>` 정적 주입(동적 주입·StrictMode 이중실행 불안정 → 정적 전환, StrictMode 제거). `https://` 명시 필수. 키는 `.env.local`(REACT_APP_*, gitignore). **카카오맵 유지**(한국 정확도), SaaS 해외확장 시 구글맵 재검토.
- Functions는 Blaze 플랜 필요(`createDriver`/`deleteDriver` 등). `.env.local`은 PC 이동 시 수동 재생성.
- 비용(자체운영 1만명/일 기준): 월 약 4~6만원. 진짜 스케일 한계 = 300대+동시 스트리밍/고객사 100+/동접 10만+.

## 7. 단계별 로드맵 (기획 우선순위 — 갭 판정 기준)
- **MVP 1단계(핵심)**: 기사 로그인→배차→운행→GPS / 관리자 실시간 지도 관제 / 고객사 실시간 위치조회
- **2단계**: 노선·배차 관리 / QR 탑승 체크인 / 탑승현황 분석
- **3단계**: 푸시 발송 / 운행일지·정산 / 고객사 계정 분리(멀티테넌트)
- **SaaS 확장(후순위·의도적 보류)**: 슈퍼관리자·빌링·타사 온보딩
- 실제 개발 순서: 기사앱 → 관리자 기본 → 승객 기본 → 관리자 확장 → 고객사 권한분리
