## 명령어
- 개발: `npm start` (http://localhost:3000)
- 빌드: `npm run build` → `build/` (Hosting public 디렉터리)
- 테스트: `npm test` (CRA watch). **실 테스트 없음**(App.test.js 스텁). 별도 lint 단계 없음.
- 배포(**사용자 명시 요청 시에만**): `firebase deploy` = Hosting+Functions+Firestore rules/indexes 동시. Functions만: `cd functions && npm run deploy`. 에뮬레이터: `cd functions && npm run serve`.
- `functions/`는 독립 npm 패키지(CommonJS) — 루트와 별도 `npm install` 필요.

## 데이터 흐름 — GPS 파이프라인
`lib/gps.js startGPS` = `watchPosition` + 5m/5초 스로틀 + 100m 정류장 도착 감지(routePath 주입 시 진행률 기반 통과 누락 백필 — GPS 끊김 회복, 2026-05-22) → `gps/{companyId}_{vehicleId}`(덮어쓰기) + `gpsHistory`(누적). PassengerApp/EmployeeApp/AdminApp이 `onSnapshot` 구독 → `lib/useAnimatedPositions.js`(rAF lerp)로 마커 보간. AdminApp 시뮬레이터 탭은 `sendGPS` 직접 호출. **콜드스타트**: 진입 시 `getCurrentPosition` 1회 선발행(출발 직후 공백 방지) + `onGpsError` 콜백(권한/TIMEOUT 상위 전파, DriverApp 안내). **통신 복구**(2026-05-28): `lib/useOnlineRecover.js`(`window.online` 이벤트 + 옵션 `forceFirestoreReconnect`로 `disableNetwork→enableNetwork`) tick을 DriverApp/PassengerApp/EmployeeApp HomeTab onSnapshot deps에 추가 → 오프라인→온라인 전이 시 stale 리스너 자동 재구독. DriverApp은 driving=true 시 `triggerHeartbeat(watchId)` 1회 호출(`gps.js` heartbeatRegistry에 캡쳐된 lastPos로 즉시 sendGPS) → 승객앱 마커 즉시 신선화. **위치 소스 이중 라이터(2026-07-08 RQ#2 유비칸/busin)**: 차량마다 `vehicles/{id}.gpsSource` = `mobile`(기본·클라 startGPS) | `device`(GPS 단말). device 차량은 신규 CF `pollDeviceVehicleGps`(onSchedule 1분·us-central1)가 busin.co.kr `CarLocationAll`(carId, 키불필요·서버 fetch) 최신 좌표를 **sendGPS와 동일 필드**로 `gps/{cid}_{vid}`에 write(`source:"device"`·15분 신선도 가드·오늘 배차로 route/driver 확보·**운행 시간 창 가드 `computeGpsWindow`**로 노선 시간표(`departTime`+정류장 `offsetMin`) 밖 좌표 차단[device 상시신호에 mobile 의 기사 수동 on/off 대응물, departTime 미설정 노선=게이트 없음]) → 소비측(MapTab/승객·직원앱) 코드 0 변경 표시. 번호→carId 매핑은 onCall `resolveBusinCarId`(CarAlloc 조회). DriverApp은 device면 startGPS skip(이중쓰기 방지). **정적QR은 device 차량 미포함**(후속 RQ)·**서버측 100m 도착감지는 폴러에 포함**(2026-07-09). 상세 @.claude/functions.md.

## 데이터 흐름 — ETA 산출(chain plan-first + 진척률 안분, 2026-05-28~29)
`lib/stopSchedule.js computeStopEstimates`는 정류장 order 순회 + 단조증가 estMs 강제. **`segTravelMs(a,b)` = 계획 offsetMin 델타 우선** — 둘 다 offsetMin 있으면 `(offsetB-offsetA)*60*1000`(DWELL 가산 X — offsetMin 자체가 정차 포함된 진입시각 차이), 한쪽 누락 시 geometric(routePath/직선 + DWELL) 폴백. chain 전파 = `actualLast + Σ(plan 델타) = plannedMs[i] + (actualLast-plannedLast)` → "각 정류장 실 도착시간 기준으로 다음 정류장까지 미리 설정한 offsetMin만큼 더해 정밀 예측". next 정류장 GPS 가중 **완전 제거(0%)** — 터널·약전계 GPS 노이즈에서 ETA 출렁임 차단. **2026-05-29 routePath 진척률 안분(next 한정)**: routePath+busProgress 있으면 `actualProgress = (busProgress-stopProgress[i-1])/segDist`, `expectedProgressByTime = elapsed/expectedTotalMs`, `slowFactor=max(1, expectedByTime/actualProgress)`(빠른 방향 1 클램프 — "갑자기 곧 도착" 점프 차단), `remainingMs=(1-actualProgress)*expectedTotalMs*slowFactor`. actualProgress≥0.95=ARRIVING_BUFFER_SEC(45초)·≤0.05=노이즈 skip. source='gps'. 이전엔 chain 채택값이 정류장 사이에 정적이라 자연 감소만 일어나 도착 직전 큰 점프 → useSmoothedEta가 raw 채택 → "곧 도착" 도약 결함. **`delaySec`는 가드 적용 *전* raw 후보(chain→plan) 기준** — 단조증가/과거금지 가드가 음수(조기) 지연을 양수(지연)로 뒤집던 결함(사용자 호소 #1) 차단. **useSmoothedEta jumpThresholdSec 300→180**(진척률 안분으로 자연 변동 → 정류장 통과 시점만 즉시 raw). 단조증가(MIN_STOP_GAP_SEC=60)·과거금지(MIN_FUTURE_BUFFER_SEC=30)·MIN_EFFECTIVE_SPEED_KMH 보호장치 유지. 출력 계약(stopId/plannedAt/estimatedAt/delaySec/status/source) 절대 불변 → useSmoothedEta/formatPassengerEta/describeEtaSource/formatDelayLabel 호환.

탑승 모드 **4번째**(동적 QR·승객 발행 QR·정적 QR 에 이어). 참고=레거시 버스인3 NFC(`file/20260722/버스인NFC태깅_사용설명서.pptx`)·스위스관광 `swsfirebase/swstagsys`(Web NFC 선례). 기사앱(`/driver`) NFC 탭 → `NDEFReader.scan()`(사용자 제스처 필수) → `onreading.serialNumber` → `lib/nfc.js normalizeNfcUid` + `createTagCooldown(2000)`(카드 대고 있으면 연속 발화) → CF `boardNfc` 가 카드→탑승자 조회·판정·적재 → 화면은 등록/이미탑승/미등록 3분기만 렌더(판정 로직 클라 0). **🔴 Web NFC = Android Chrome + HTTPS 전용** — iOS Safari·데스크톱엔 `NDEFReader` 부재라 NFC 탭 자체를 숨기고(`isWebNfcSupported()`) 탭 안에서도 QR 폴백 안내. 이 제약 때문에 **승객 자가 카드등록은 채택하지 않고**(레거시는 네이티브 앱이라 가능했음) 협력사 포털 관리자 등록으로 설계. **카드 UID 확보 경로 4종**(기존 사원증 재사용이면 회사에 UID 목록이 없다 — 카드를 한 번씩 읽어내는 수밖에 없고, **아이폰 승객은 웹으로 자기 카드를 못 읽어 자가등록을 채택하지 않음**·way 결정): ① **협력사 포털 카드 일괄 등록**(주력·`REG_MODES.NFC`) — 담당자가 안드로이드 1대로 승객 줄 세워 연속 태깅(이름 선택→태그→자동 다음·진행률 표시) ② **기사앱 등록 대행**(현장 예외·`mode="register"`) — 탑승 모드에서 미등록 카드가 찍히면 "이 카드 등록하기" 버튼이 UID 를 들고 등록 모드로 넘어가 카드 재태깅 불요 ③ **엑셀 일괄**(`NFC카드번호` 선택 컬럼 — 카드 신규 발주로 업체가 UID 목록을 준 경우) ④ 협력사 포털 개별 수기 입력·AdminApp "부정승차" 탭 UID 복사. ①②③④ 모두 CF `registerNfcCard`/`importEmployees` 로 수렴하고 정규화·중복검사는 서버가 강제. 상세 @.claude/issues.md.
