## 한눈에

*   QR 탑승 방식은 차량 고정 바코드 기반으로, 승객 선택 노선과 태깅 차량 불일치 시 탑승 차단.
*   그룹(관리회사) 개념 도입으로 노선/차량/바코드 설정 통합, 탑승자/어드민/현황은 서브 회사별 분리.
*   승객 앱 UI/UX 개선: 노선도/탑승 계획 통합, 아이콘 색상 커스터마이징, 지도 확대/축소 기능.
*   차량 운행 현황 실시간성 및 정확도 개선, 슬리핑 차일드 관리자 기능 강화.
*   초기 비밀번호 '0000' 유지 및 로그인 화면 안내, 비로그인 고객 문의는 카카오톡 채널 연동.
*   유비칸 단말기 도입 확대 및 연동 안정화, 안내 방송 시스템은 USB 연결 방식 검토.

## 요구사항

*   **QR 탑승 차단**: 승객용 앱에서 노선 선택과 태깅 차량 불일치 시 탑승 차단. 〔M1〕 "선택 노선과 태깅 차량이 불일치하면 "해당 노선의 QR이 아닙니다" 안내 후 탑승 차단"
*   **운행 상태 실시간 최신화**: 노선별 차량 위치 및 운행 상태 실시간 최신화. 〔M2 01:57〕 "노선별로 다 최신화가 돼야 되는데 차량 위치든 노선이든."
*   **운행 종료 상태 표시**: 운행 종료된 노선은 "운행 중" 상태로 표시되지 않도록. 〔M2 01:57〕 "노선 바꿨는데도 현재 운행 종료된 노선인데도 운행 상태가 변경되지 않고 계속 운행 중으로 있었다."
*   **관리자 시간 설정**: 관리자가 운행 시작 30분 전/후 설정 값을 직접 체크하고 변경 가능. 〔M2 02:17〕 "운행 30분 전 30분 후 그거를 좀 관리자가 체크해 가지고 바꿀 수 있게 좀 해 주시면."
*   **다회 운행 차량 시각화**: 승객이 특정 노선의 여러 운행 시간대 차량을 볼 수 있도록 관리자 설정 기능 제공. 〔M2 02:47〕 "승객들을 볼 수 있게"
*   **복수 차량 지도 표시**: 한 노선에 여러 대 차량 배차 시, 모든 차량이 지도상에 표시. 〔M2 03:57〕 "네 개를 해 놓고 그 노선에 대해서 각 차량이 보이게끔 해야 되는 거네."
*   **초기 비밀번호 안내**: 메인 로그인 화면에 "초기 비밀번호는 000000입니다" 문구 표시. 〔M3 01:45〕 "네. 그리고 그 메인 로그인 화면에도 기동과 같이 초기 비밀번호는 000000입니다라고 표시해 주고."
*   **노선 텍스트 강조**: 노선 정보 화면에서 특정 텍스트(예: 조기 출근)를 진하게 표시. 〔M3 04:03〕 "네. 이런 조기 출근 이런 거를 좀 진하게 해 달라."
*   **홈페이지 연결 버튼**: 하단 탭 또는 문의하기 탭에 홈페이지 연결 버튼 추가. 〔M3 04:28〕 "홈페이지로 가는 아, 연결 버튼 하나 만들어 줄까?"
*   **QR 태깅 소리**: QR 태깅 시 소리가 나도록 기본 설정 활성화 (사용자 조절 가능). 〔M3 09:45〕 "기본 설정은 소리 나게끔 이제 하게끔 해 줄 순 있어."
*   **앱 운행 시간 표시 오류 수정**: 승객용 앱에서 버스 도착 시간이 실제 도착 시간(현재 시각)으로 변경되는 현상 수정. 〔M4 01:19〕 "처음 내려오면 시간이 이렇게 되는데 한 번 내려왔다가 다시 올라오면은 시간이 도착 시간으로 바뀌는 현상이 있어요."
*   **앱 경로 표시 오류 수정**: 운행 종료 후 시간이 지나면 운행 완료된 경로(회색)가 파란색으로 다시 활성화되는 현상 수정. 〔M4 02:16〕 "이게 시간 어느 이상을 벗어나면은 그냥 갑자기 튀어 버려요."
*   **슬리핑 차일드 내역 확인**: 슬리핑 차일드 태그 찍은 내역(언제/어디서)을 관리자 화면에서 확인 가능하도록 추가. 〔M4 03:51〕 "이게 기서 블로 대시보드에 뜨긴 하는데 이 내역 좀 언제 찍었고 어디 찍었고 요런 내역 좀 제가 볼 수 있고"
*   **슬리핑 차일드 필터링**: 슬리핑 차일드 관리 페이지에서 특정 노선(예: 하교 노선)만 선택하여 볼 수 있도록 필터링 기능 추가. 〔M4 04:36〕 "하교 거는 하교 때만 좀 이제 제가 볼 수 있고 관리를 할 수 있는 페이지 하나 만들어 주시면"
*   **비로그인 고객 문의**: 로그인 페이지에 동영케어 카카오톡 채널 안내 문구 및 링크 추가하여 비로그인 사용자 문의 유도. 〔M5 05:17〕 "카카오톡 채널 안내 동영케어 안내 페이지를 링크를 넣어야겠다."
*   **지도 확대 기능**: 지도 확대 기능 추가 및 On/Off 기능 제공. 〔M6 01:01〕 "지도 확정 기능을 온오프를 해서"
*   **버스 도착 시간 예측 정확도**: 버스 도착 시간 예측의 정확도 향상 (초정밀, 10초 단위). 〔M6 01:24〕 "초정밀 얘긴데"
*   **예측값 변경 문제 개선**: 버스 도착 시간 예측값이 갑자기 바뀌는 문제 개선. 〔M6 03:05〕 "갑자기 4분으로 바뀌어 가지고 한 바퀴를 돈다 요 얘기예요."
*   **백그라운드 앱 문제 해결**: 운행 중 백그라운드 앱으로 인한 GPS 데이터 수집 문제 해결. 〔M6 01:45〕 "그거를 이제 운행 중에 자기 뭐 사람 전화도 올 수 있고"

## 확정된 결정

*   **QR 바코드**: 차량 기준 고정 1개 사용. 〔M1〕
*   **QR 노선 매핑**: 노선/거래처 정보는 승객이 앱에서 선택한 값으로 매핑. 〔M1〕
*   **거래처별 바코드**: 거래처별 바코드 분리 불필요. 〔M1〕 "거래처별 바코드 분리 불필요"
*   **그룹 설정**: "그룹" 상위 개념 신설; 노선/차량/바코드 세팅은 그룹 단위 통합, 탑승자 관리/협력사 어드민/탑승 현황은 서브 회사별 분리. 〔M1〕 ""그룹" 상위 개념 신설"
*   **앱 UI 커스터마이징**: 거래처별 메인 컬러 지정(컬러 코드 입력), 회사 로고 삽입 및 위치/사이즈 조정 지원. 〔M1〕 "거래처별 메인 컬러 지정(컬러 코드 입력)"
*   **매뉴얼**: 협력사 포탈/승객앱 매뉴얼은 최소 요약본으로 제작·제공. 〔M1〕
*   **노선 선택 UI/UX 통합**: 승객용 앱에서 노선도와 탑승 계획을 상단 노선도로 통합하고 하단 기능은 없앰. 〔M2 08:16〕 "위에 거로 해 놓고 아래 거에 있었던 노선 내가 탈 탑승장 도착 알림 클릭하는 거를 위로 통합해서 한 줄로 표현하자 이거네."
*   **하단 아이콘 색상**: 하단 앱 아이콘 색상을 통일하여 커스터마이징 가능하도록 지원. 〔M2 09:30〕 "하단 앱의 색깔을 좀 통일해서 갔으면 좋겠다."
*   **콜센터 연동**: Buslink 앱의 운행 시작 신호를 콜센터 시스템에서 확인할 수 있도록 추가. 〔M2 27:13〕 "신호를 하나 더 넣는 거야. 버스 링크 앱. 그래서 운행 시작이 됐냐 안 됐냐."
*   **QR 보안 취약점 수정**: QR 코드 스캔 후 아무 정보로 로그인되는 보안 취약점 수정. 〔M3 01:14〕 "그래서 일단 요거가 막아져야지. 아, 그거 수정해야 될 것 같다."
*   **초기 비밀번호**: 신규 등록 계정의 초기 비밀번호는 '0000'으로 설정하며, 로그인 화면에 해당 비밀번호 안내 문구 추가. 〔M5 01:11〕 "그럼 놔두고 그냥 초기 비밀번호만 접속 가능하게끔 계속 해주면 될 거 같고."
*   **유비칸 매핑**: 유비칸 시스템에서 기사명보다 차량 번호를 기준으로 매핑. 〔M3 03:22〕 "차량이 중요해요."
*   **홈페이지 링크 명칭**: 홈페이지 링크 버튼의 명칭은 '홈페이지'로 한다. 〔M3 04:59〕 "그냥 홈페이지로 쓸게."
*   **문의하기 기능 통합**: 문의하기 탭은 홈페이지로 연결하고, 문의나 전화 연결 기능은 연결된 홈페이지 내에서 처리. 〔M3 05:47〕 "아, 그러면은 문의를 홈페이지로 한 다음에 전화를 하더라도 그냥 거기서 해라."
*   **AI 데이터 학습**: AI 데이터 학습 시 데이터의 양(다수 입력)을 우선하며, 정밀한 형식보다는 많은 데이터를 입력하는 것이 더 효과적. 〔M3 08:13〕 "두 개 선택하라면 나는 많이 넣는 거야."
*   **유비칸 단말기 발주**: 모든 외부 사업장에는 휴대폰 대신 유비칸(시거잭 방식) 단말기를 발주하여 운행 관리. 〔M3 10:36〕 "외부도 다 그냥 시거로 다 발주하고."
*   **슬리핑 차일드 현황**: 슬리핑 차일드 태그 기록 현황을 관리자 화면에 추가. 〔M4 04:00〕 "아 당연히 있어야지. 그거 그 저기 관리자 화면에 넣어 줄게. 슬리핑 차일드 현황."
*   **슬리핑 차일드 관리 페이지**: 슬리핑 차일드 기능을 운영하는 노선만 선택하여 관리할 수 있는 페이지를 추가 개발. 〔M4 04:56〕 "오케이 알았어."
*   **CS 정류장 업데이트**: CS 정류장 관련 업데이트 완료 사항은 영업담당자가 회신 진행. 〔M5 01:31〕 "그냥 점검 완료했다고 내일 한번 써보시라고 하면 될 거 같아."
*   **유비칸 연동 모니터링**: 유비칸 연동 이슈는 내일까지 모니터링 후, 문제 지속 시 시스템 관리자에게 공유하여 추가 조치 논의. 〔M5 06:14〕 "일단 내일까지는 모니터링 한번 해보겠습니다."
*   **학원 노선 예측 모니터링**: 학원 노선에 대한 예측 정확도 모니터링 및 분석 실시. 〔M6 27:04〕 "그러면 학원 노선을 한 며칠 동안 보자."
*   **운세미 태그리스 유지**: 운세미 시스템은 태그리스 (Tagris) 사용 유지. 〔M6 27:38〕 "아 네 네. 태그리스 하시라고 그냥 그대로 가기로 했어요."

## 화면·기능 설계

*   **승객 앱**:
    *   **QR 탑승**: 승객이 선택한 노선과 태깅 차량 불일치 시 "해당 노선의 QR이 아닙니다" 안내 후 탑승 차단. 〔M1〕 "선택 노선과 태깅 차량이 불일치하면 "해당 노선의 QR이 아닙니다" 안내 후 탑승 차단"

## 데이터·연동

*   **QR 바코드**: 차량 기준 고정 1개. 〔M1〕
*   **QR 노선 매핑**: 노선/거래처 정보는 승객이 앱에서 선택한 값으로 매핑. 〔M1〕
*   **그룹 설정**: "그룹" 상위 개념 신설 시, 노선/차량/바코드 세팅은 그룹 단위 통합. 〔M1〕 "노선·차량·바코드 세팅은 그룹 단위 통합"
*   **콜센터 연동**: Buslink 앱의 운행 시작 신호를 콜센터 시스템에서 확인할 수 있도록 추가. 〔M2 27:13〕 "신호를 하나 더 넣는 거야. 버스 링크 앱. 그래서 운행 시작이 됐냐 안 됐냐."
*   **유비칸 매핑**: 유비칸 시스템에서 기사명보다 차량 번호를 기준으로 매핑. 〔M3 03:22〕 "차량이 중요해요."
*   **AI 학습 데이터**: AI 데이터 학습 시 데이터의 양(다수 입력)을 우선하며, 정밀한 형식보다는 많은 데이터를 입력하는 것이 더 효과적. 〔M3 08:13〕 "두 개 선택하라면 나는 많이 넣는 거야."
*   **CS 정류장 데이터**: 서버와 대량 등록 시 정류장 데이터 미스매치 발생하여 업데이트 완료. 〔M5 01:22〕 "그건 이제 서버랑 대량 등록할 때랑 약간 미스매치되는 게 있어서 그건 업데이트 했고."
*   **유비칸 연동 모니터링**: 유비칸 연동 이슈는 내일까지 모니터링 후, 문제 지속 시 시스템 관리자에게 공유하여 추가 조치 논의. 〔M5 06:14〕 "일단 내일까지는 모니터링 한번 해보겠습니다."
*   **예측 시간 로직**: 현재 예측 시간은 카카오 내비게이션 기준 로직으로 개발되었으며, 직전 정류장 도착 시 리셋하여 재측정하는 방식을 사용. 〔M6 17:38〕 "카카오 내비게이션 기준으로" 〔M6 17:50〕 "직전 정류장에 도착을 하면 직전 정류장에서 다시 리셋을 해서 측정을 해요."
*   **예측 로직**: 예측 로직은 정류장 간 거리를 균등 배분하고 교통 상황을 반영하여 보수적으로 예측. 〔M6 21:04〕 "거리를 균등 배분해서" 〔M6 20:29〕 "예측하게 보수적으로 알려주는 거예요."
*   **운세미 시스템**: 운세미 시스템은 태그리스 (Tagris) 사용 유지. 〔M6 27:38〕 "아 네 네. 태그리스 하시라고 그냥 그대로 가기로 했어요."
*   **Tagris 연동**: Bus Link에서 Tagris 연동 시 Native 앱 개발 필요. 〔M6 28:18〕 "네이티브로 가야 돼."

## 업무 규칙·예외

*   **QR 탑승 불일치**: 승객이 앱에서 선택한 노선과 태깅 차량이 불일치하면 "해당 노선의 QR이 아닙니다" 안내 후 탑승 차단. 〔M1〕 "선택 노선과 태깅 차량이 불일치하면 "해당 노선의 QR이 아닙니다" 안내 후 탑승 차단"
*   **그룹별 관리**: "그룹" 상위 개념 신설 시, 탑승자 관리/협력사 어드민/탑승 현황은 서브 회사별로 분리하여 관리. 〔M1〕 "탑승자 관리·협력사 어드민·탑승 현황은 서브 회사별 분리"
*   **초기 비밀번호**: 신규 등록 계정의 초기 비밀번호는 '0000'으로 설정하며, 당분간 유지 및 접속 가능하도록 조치. 〔M5 01:11〕 "그럼 놔두고 그냥 초기 비밀번호만 접속 가능하게끔 계속 해주면 될 거 같고."
*   **QR 보안 취약점**: QR 코드 스캔 후 아무 정보로 로그인되는 보안 취약점 수정. 〔M3 01:14〕 "그래서 일단 요거가 막아져야지. 아, 그거 수정해야 될 것 같다."
*   **문의하기 처리**: 문의하기 탭은 홈페이지로 연결하고, 문의나 전화 연결 기능은 연결된 홈페이지 내에서 처리. 별도 전화 연결 버튼 없음. 〔M3 05:47〕 "아, 그러면은 문의를 홈페이지로 한 다음에 전화를 하더라도 그냥 거기서 해라."
*   **운행 관리 단말**: 모든 외부 사업장은 휴대폰 대신 유비칸(시거잭 방식) 단말기를 발주하여 운행 관리. 〔M3 10:36〕 "외부도 다 그냥 시거로 다 발주하고."
*   **안내 방송 시스템**: Bluetooth 연결/페어링 문제로 기존 Buslink 탑재 기능 사용 불가하며, 태블릿 도입 또는 USB 연결 방식 검토 필요. 〔M2 14:45〕 "블루투스를 연결해야 될 거 아니야. 페어링을 해야 되고 약간 여러 가지 문제가 있어."
*   **GPS 데이터 수집**: 운전 중 핸드폰 앱 우선순위 충돌 문제로 APK가 백그라운드에서 강제 종료되거나 우선순위가 밀리면 정확한 위치 정보 수집 불가. 〔M6 25:06〕 "얘가 내려간다 하면은 중간에 끊겨요."
